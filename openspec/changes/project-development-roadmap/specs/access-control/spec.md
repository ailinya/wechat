# 认证与访问控制

## Purpose

统一平台用户身份、会话有效性和业务操作权限，使管理员、运营、编辑和审核人员按照实际授权工作。任何受保护操作均须由服务端验证，页面隐藏按钮不能替代权限检查，凭据与会话失效后不能继续访问业务资源。

## ADDED Requirements

### Requirement: 登录与当前身份
系统 SHALL 使用有效且启用的用户凭据建立有期限的会话，并返回当前用户及其有效权限；错误凭据或禁用账号 MUST 被拒绝。

#### Scenario: 正常登录与恢复身份
- **WHEN** 启用用户使用正确凭据登录并随后查询当前身份
- **THEN** 系统返回该用户及有效权限，刷新页面后仍可在会话有效期内恢复身份

#### Scenario: 拒绝无效登录
- **WHEN** 用户提供错误凭据或账号已禁用
- **THEN** 系统拒绝建立会话，响应不包含密码、密码哈希或内部敏感信息

### Requirement: 会话撤销与失效
系统 SHALL 支持注销并撤销对应会话；已过期、已撤销或用户已禁用的会话 MUST 不能授权后续受保护请求。

#### Scenario: 注销后重用会话
- **WHEN** 用户注销后使用原会话再次读取业务数据
- **THEN** 系统拒绝请求并要求重新认证

#### Scenario: 会话期间账号被禁用
- **WHEN** 管理员禁用一个已有有效会话的用户，用户再次发起受保护请求
- **THEN** 系统拒绝请求，不允许继续使用原有业务权限

### Requirement: 服务端操作权限
系统 MUST 对受保护资源及写操作执行服务端权限检查，区分未认证与已认证但无权限；前端、直接 API 请求及异步动作入口 MUST 遵循相同授权边界。

#### Scenario: 绕过页面直接审核
- **WHEN** 只有编辑权限的用户直接调用审核通过接口
- **THEN** 系统返回无权限结果，文章审核结论保持不变

#### Scenario: 未认证访问
- **WHEN** 未登录调用方请求受保护业务接口
- **THEN** 系统返回未认证结果且不披露业务数据

### Requirement: 用户角色与权限维护
系统 SHALL 允许具备管理权限的人员维护用户信息、状态、角色及角色权限，提供管理员、运营、内容编辑和内容审核的初始权限配置；有效权限 MUST 反映管理变更。

#### Scenario: 修改角色权限
- **WHEN** 有权限的管理员撤销某角色的发布确认权限，该角色用户再次确认发布
- **THEN** 系统拒绝该动作，当前身份查询反映已撤销的权限

#### Scenario: 普通用户尝试提权
- **WHEN** 无用户管理权限的人员提交角色分配或权限变更
- **THEN** 系统拒绝变更，用户和角色记录保持不变

### Requirement: 认证凭据保护
系统 MUST 保护存储中的密码与会话凭据，普通查询响应、客户端页面和操作日志不得披露密码哈希、有效会话密钥或长期授权令牌。

#### Scenario: 查询用户及登录日志
- **WHEN** 有权限的人员查询用户详情或认证操作记录
- **THEN** 系统返回必要身份与结果信息，不返回密码哈希、密码及有效会话凭据
