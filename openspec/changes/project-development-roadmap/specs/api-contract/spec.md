# API 通用契约

## Purpose

为前端和其他受授权调用方提供一致、可校验的业务接口边界，明确资源标识、列表分页、时间表示、错误信息及异步受理含义。接口契约必须能用于生成客户端类型和联调验证，防止页面与服务端对同一操作产生不同理解。

## ADDED Requirements

### Requirement: 资源接口与文档一致
业务 API SHALL 使用 `/api/v1` 前缀及 snake_case JSON 字段，资源标识使用 UUID；已交付接口 MUST 有对应机器可读契约，描述输入、输出、权限和主要失败响应。

#### Scenario: 根据契约调用业务接口
- **WHEN** 调用方按已交付接口的契约提交合法 JSON 请求
- **THEN** 返回结构和状态码与契约一致，不要求调用方猜测未声明的必需字段

### Requirement: 一致的列表分页
列表接口 SHALL 支持 page、page_size、声明的筛选和稳定排序，并返回 items、total、page、page_size；非法分页或筛选输入 MUST 被明确拒绝。

#### Scenario: 分页查询稳定数据集
- **WHEN** 调用方使用相同筛选和排序读取静态数据集的连续页
- **THEN** 各页返回稳定顺序及一致总数，不因排序值相同而随机遗漏或重复资源

### Requirement: 时间表示与时区
API 时间戳 MUST 使用带 UTC 时区的 ISO 8601 表示，用户界面 SHALL 按所选时区显示；调度请求 MUST 明确时区或绝对执行时间。

#### Scenario: 确认定时发布时间
- **WHEN** 用户在 Asia/Shanghai 界面选择发布时间并提交
- **THEN** 接口持久化和返回相应 UTC 时间，页面还原为用户确认的本地时间

### Requirement: 稳定且安全的错误响应
错误响应 MUST 包含稳定 code、可读 message 及必要的 field_errors，区分未认证、无权限、状态/版本冲突和输入不合法；响应 MUST 不披露敏感堆栈或凭据。

#### Scenario: 请求包含非法字段值
- **WHEN** 调用方提交超出允许范围的参数
- **THEN** 系统返回校验失败及字段信息，不接受请求后再伪装为成功

#### Scenario: 保存基于过期版本
- **WHEN** 调用方以旧的基准版本保存已被他人修改的文章
- **THEN** 系统返回 HTTP 409 及版本冲突信息，不静默覆盖当前版本

### Requirement: 异步受理契约
需后台执行的操作 SHALL 在成功受理时返回 HTTP 202、async_job_id 和关联业务对象标识，提供查询入口；失败或未满足受理条件 MUST 不伪装成已受理任务。

#### Scenario: 提交立即采集
- **WHEN** 合法立即采集请求已被可靠受理
- **THEN** 响应提供对应执行记录和异步任务标识，调用方可据此查询最终状态

### Requirement: 副作用请求幂等约定
运行采集、启动创作、确认发布及重试等接口 SHALL 接受 Idempotency-Key，并在相同用户及动作作用域内绑定请求内容；同键不同内容 MUST 返回冲突。

#### Scenario: 网络重发相同请求
- **WHEN** 调用方使用相同幂等键和内容重发已受理请求
- **THEN** 返回原业务结果或原任务标识，不再次创建同一副作用

#### Scenario: 幂等键被不同内容重用
- **WHEN** 调用方在同一作用域使用相同幂等键提交不同发布账号或参数
- **THEN** 系统拒绝请求并返回冲突，不将旧响应误配为新请求结果
