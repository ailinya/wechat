# 智媒助手系统技术设计总览

## 1. 文档目的

本文概述智媒助手首期系统架构、前后端模块、业务流程和开发顺序。前端模块、数据模型与 API 契约分别维护在独立文档中：

- [前端模块设计](frontend-design.md)
- [数据库设计](database-design.md)
- [API 设计](api-design.md)
- [采集增强设计](collection-design.md)（主题搜索、链接发现、LLM 素材分析，待实施）

设计依据为 `AGENT.md`、`doc/instruction/PRD.md` 和 `doc/html/` 原型。原型中的 JSON 是演示数据，不作为生产数据模型；AGENT.md 的 PRD 引用已修正。已实现基础与待实施增强分别以代码、任务和阶段证据为准。

## 2. 技术架构

```text
React + TypeScript + Vite
          │ REST / JSON
          ▼
FastAPI 模块化单体 ───────── PostgreSQL + pgvector
          │                          ├─ 业务数据、正文、版本和任务记录
          ├─ Redis Broker             └─ 素材分块向量及语义检索
          ▼
     Celery Worker ── LangGraph 创作流程
          │
          └──────────────────── RustFS 文件存储
                                  图片、文档和附件
```

- 前后端分离，后端首期采用模块化单体，不按微服务拆分。
- FastAPI 提供 REST API；Celery Worker 处理采集、解析、embedding、AI 创作、同步和发布等异步工作；Celery Beat 负责定时触发。
- Redis 负责 Celery Broker，可选用于短期任务结果查询；业务状态必须持久化到 PostgreSQL。数据库写入与任务投递通过 outbox/dispatcher 衔接。
- PostgreSQL 保存业务数据、Markdown 正文、审核/发布历史和 pgvector 向量；RustFS 保存二进制文件，数据库保存对象键和元数据。
- LangGraph 编排 Agent 内部步骤。Agent 可以检索素材和生成内容，不能改变审核结论或跳过运营发布确认。
- 采集增强采用固定流程：搜索/来源发现 adapter → 抓取 → 正文提取 → 可选 LLM 分析 → 入库决策；不引入采集 Agent。搜索、分析和模型配置经后端服务调用，复用 Celery/outbox。公共模型服务先支持素材分析，再供 LangGraph 创作复用。

## 3. 前端模块

前端按八个一级业务模块组织；页面清单、路由建议、模块关系图和关键交互见[前端模块设计](frontend-design.md)。

## 4. 后端模块

后端采用 `api/routes → schemas → services → repositories/models` 分层。跨模块写操作通过领域服务完成；采集器、模型供应商、文件存储和微信接口通过 adapter 隔离。

| 模块 | 职责 |
| --- | --- |
| `auth` | 登录、用户、角色、权限和鉴权 |
| `collection` | 来源适配、主题搜索、文章链接发现、采集任务、候选和阶段执行记录 |
| `materials` | 入库决策、去重/新进展、正文快照及修订、LLM 分析建议、标签分类、文件和检索 |
| `creation` | 自动规则、素材/主题创作、条件判断和任务记录 |
| `agent` | LangGraph 状态图、模型和工具调用、生成结果 |
| `articles` | 草稿、版本、编辑、排版和审核状态 |
| `publishing` | 发布单、运营确认、微信发布和重试 |
| `accounts` | 微信授权、权限检测和素材同步 |
| `analytics` | 工作台、统计聚合和指标快照 |
| `settings` | 模型配置、通知、平台参数和操作日志 |

密钥保存为加密凭据或外部 secret 引用，不返回前端、不写入普通日志。详细表结构见[数据库设计](database-design.md)，接口边界见[API 设计](api-design.md)。

## 5. 核心业务流程

### 采集入库

```text
定时/手动触发 → 创建运行配置快照、异步任务与 outbox
→ 指定来源发现文章链接 / 按主题调用搜索服务
→ 候选规范化和范围检查 → 抓取原文并保存结果
→ 正文/日期提取 → 关键词与时间筛选 → 完全重复匹配
→ 可选 LLM 分析与疑似重复/新进展比较
→ 满足条件自动入库 / 等待人工筛选
→ 创建素材正文版本并异步生成 embedding
→ 素材就绪事件 → 按任务开关和关联规则检查是否触发创作
```

### 素材/主题创作

```text
提交主题或规则触发 → 检查素材数量、正文、相关度、重复主题和活跃任务
→ 关键词与向量检索素材 → 人工预览选择或自动筛选
→ Celery Worker 调用 LangGraph 分析、提取主题并生成文章
→ 保存生成结果、文章及文章版本 → 进入待审核
```

### 编辑、审核与发布

```text
编辑草稿 → 保存新文章版本 → 提交该版本审核
→ 审核员保存检查项和结论
→ 通过后创建发布单 → 运营确认账号、方式和时间
→ Worker 执行前再次校验版本审核状态和账号权限
→ 保存每次外部发布尝试 → 成功更新状态，失败保留原因并允许重试
```

## 6. 开发任务顺序

### 阶段一：工程基础

- 初始化 React/TypeScript/Vite 和 FastAPI 项目、配置与本地运行方式。
- 建立 PostgreSQL migration、pgvector、统一错误/分页格式和认证权限。
- 建立 Redis、Celery Worker/Beat、异步任务状态、outbox dispatcher 和幂等约定。

### 阶段二：采集和素材闭环

- 实现来源、采集任务、执行记录、结果入库和解析重试。
- 实现 RustFS 文件、素材 Markdown 版本、去重/事件更新关系、分类标签和引用追溯。
- 在原基础上实施增量任务 3.13–3.28：工具验证、主题搜索/RSS/栏目发现、正文提取、公共模型配置、LLM 分析、人工保护及独立验收。旧任务完成记录不代表增强完成。
- 实现 embedding 生成、关键词与向量检索预览。

### 阶段三：智能创作与文章

- 实现创作规则、自动触发、素材/主题创作、条件判断和幂等。
- 实现 LangGraph 生成流程、原始生成结果、失败恢复和文章版本编辑。
- 实现文章排版、素材引用、审核队列、退回复审和版本校验。

### 阶段四：账号与发布

- 实现微信公众号授权回调、权限检测、默认账号和素材同步记录。
- 实现发布订单、人工确认、定时校验、发布尝试历史和幂等重试。

### 阶段五：运营管理与验收

- 实现工作台、统计、公众号指标快照、通知、设置和完整审计日志。
- 验收去重与事件更新保留、素材复用/引用、任务幂等重试、版本复审、无确认不发布和外部服务失败恢复。

## 7. 实现前待确认

- embedding 模型与维度决定首次 `vector(D)` 迁移；上线前需确定并记录重建向量方案。
- 搜索/解析候选 Tavily Search、feedparser、Trafilatura 及 analysis 模型须由中文来源样例验证确定，当前未接入；详情及后续任务见采集增强设计。
- 采集来源按实际合法接入能力确定，确认正文、原文链接和附件可用范围。
- 微信授权、素材同步、定时发布和运营数据按公众号真实接口权限启用。
- “修改后待复审”建议映射为新版本重新进入“待审核”，旧审核记录仍绑定旧版本。
- Markdown 是正文规范格式；发布前转换为微信图文格式，并验证图片和排版结果。
