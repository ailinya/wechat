# 采集增强设计：主题搜索与 LLM 素材分析

## 1. 范围与实施状态

本文是 `project-development-roadmap` 任务 3.13–3.28 的增量设计。服务、页面及确定性测试已实现，3.28 已补齐 DeepSeek 真实中文分析及实际 Worker 闭环验证，当前证据和限制见 [增强验收记录](../development/phase-03-enhancement.md)。原阶段 3 的交付记录不替代本增强验收。需求见 [PRD](../instruction/PRD.md)，行为规格见 [采集管理](../../openspec/changes/project-development-roadmap/specs/collection-management/spec.md)及[素材分析](../../openspec/changes/project-development-roadmap/specs/material-analysis/spec.md)。

采集由固定业务流程执行，直接调用搜索、抓取、解析和模型服务；不引入采集 Agent、自主循环搜索或多 Agent。阶段 5 的 LangGraph 创作 Agent 保持原职责。未来 Agent 可通过相同服务接口调用能力，但仍受权限、用量和入库规则约束。

## 2. 采集入口与文章发现

| 模式 | 输入与校验 | 链接发现方式 |
| --- | --- | --- |
| `source` 指定来源 | 至少一个启用的 `source_id`；关键词可空 | 文章 URL 直接作为候选；RSS 解析条目；栏目页按配置规则提取文章链接和下一页 |
| `topic_search` 主题搜索 | 非空主题、可用搜索配置；来源 ID 允许为空 | 后端将主题和关键词按固定模板组成一个查询，调用搜索 adapter；可设置 `allowed_domains` 限定网站 |

- 保留来源类型 `rss/web_page`；`web_page` 增加 `page_kind=article/list`，默认 `article`。栏目页配置文章链接和下一页选择规则，不假设任意首页都能自动识别。新 UI 必须明确区分文章页与列表页。
- 搜索服务是配置对象，不是新闻来源。搜索结果记录实际网页来源、查询、排名和搜索配置版本，不为每条结果强制创建人工维护的来源记录。主题模式不使用 `source_ids` 表达域名限制，非空值应明确拒绝，避免两套范围含义冲突。
- 关键词在主题模式参与构造搜索词；两种模式中，非空关键词均作为标题与提取正文的任一短语匹配条件（Unicode 规范化、忽略大小写，不自动分词或扩词）。LLM 相关性分析是后续语义筛选，不能替代这个显式条件。
- 日期窗口固定为本次运行开始时刻向前 `time_range_days` 天，使用 UTC。搜索提供方过滤只作预筛，抓取后按 RSS/原文的可验证发布时间复验。日期缺失或冲突时标记 `needs_review`，保留原始日期证据，不用采集时间冒充发布时间，也不自动入库。
- 候选先解析相对链接、去 fragment、规范化主机与默认端口；不盲删全部查询参数。规范化链接用于运行内防重；正文 hash 用于跨来源完全重复匹配。重复发现关系仍保留，可回溯各搜索结果或 RSS 条目。
- `allowed_domains` 默认为空，表示不额外限定公网网站；配置时按明确主机及其子域匹配（主机等于域名或以 `.` + 域名结尾），禁止字符串包含匹配。搜索结果、RSS 链接、栏目链接和重定向后的地址均经统一访问校验；不能仅信任搜索提供方的域名过滤。
- 默认每次最多保留 100 个候选、抓取 20 篇文章、每个 RSS/栏目入口访问 5 页；管理员可下调限制。抓取上限可配置为 1–100，分页上限 1–20；重试同样计入调用预算。搜索分页仅使用提供方已确认支持的方式，不自动生成新主题继续搜索。

## 3. 固定执行流程与服务边界

```text
source：文章 URL / RSS 条目 / 栏目链接 ─┐
topic_search：搜索查询 → 候选 URL ──────┤
                                     ↓
候选规范化与范围校验 → 有界抓取 → 正文/元数据提取
→ 时间及关键词筛选 → 完全重复匹配
→ 可选 LLM 单篇分析 → 疑似重复/事件新进展比较
→ 自动入库或等待人工筛选 → 素材就绪事件 → 创作规则检查
```

| 服务职责 | 输入 → 输出 | 副作用边界 |
| --- | --- | --- |
| 搜索 | 查询、域名、时间窗口、限额 → 标题/URL/摘要/提供方时间及排名 | 外部搜索请求；摘要只是发现依据 |
| 来源发现 | 来源配置、分页游标、限额 → 文章 URL 和发现证据 | 读取受限页面/订阅；不入库 |
| 抓取 | 已校验 URL → 原始响应、最终 URL、状态码 | 复用现有 adapter；HTTP 错误不可当有效正文 |
| 正文提取 | 原始响应 → Markdown、标题、日期证据、正文 hash、提取器版本 | 原始响应和解析快照持久化 |
| 素材分析 | 不可变正文、任务主题、模型/提示词版本 → 经 schema 校验的结构化建议 | 模型无搜索/审核/发布工具权限，不直接写素材字段 |
| 入库决策 | 筛选结果、分析建议、历史候选及人工决定 → 新建/关联/待筛选 | 领域服务事务写素材、关联、审计及 outbox |

复用 Celery、PostgreSQL、outbox、对象存储与既有权限。外部网络/模型调用不持有跨全流程的数据库写事务；每一步短事务领取、保存结果和推进状态，副作用前复验取消状态及输入版本。互联网搜索不调用 `/materials/search`，后者仅负责阶段 4 的库内检索。

## 4. LLM 分析与入库决策

- `analysis_enabled` 默认 `false`，兼容旧任务；启用时须选可用 `analysis` 用途模型。主题搜索本身不强制开启 LLM。模型不可用时保留采集能力，但不得静默跳过已启用的分析要求。
- 单篇输出为摘要、已有分类候选、标签建议、`relevance=relevant/irrelevant/uncertain` 及理由、关键事实/日期/数据和对应原文引用。每条事实绑定输入正文中的引用片段；无法定位的引用视为非法输出。没有主题且关键词为空时相关性返回 `not_applicable`。模型输出是提取与建议，不是已完成外部事实核验。
- 正文超出模型预算时显式失败 `input_too_large` 并保留原文，不能静默截断后宣称完成全文分析；可后续单独扩展分段分析。恶意正文只作为资料，不作为运行指令。
- 完全重复优先比较版本化规范化规则下的正文 hash，跨 URL 命中后关联已有素材，记录原来源，不重复调用模型。并发首次入库通过内容键串行化或等效事务约束避免重复副作用；hash 不能用于判断“同事件无新增”。
- 非完全重复先以规范化 URL、标题及关键词重叠检索最多 5 个历史候选（阶段 3 不依赖 pgvector）。仅对这些候选按需调用模型比较关键新增事实，输出 `duplicate/new_progress/distinct/uncertain`、目标素材修订及原文依据。URL 相同但 hash 变化不再自动等于事件新进展；没有候选不得据此宣称不存在语义重复。
- 只有 hash 完全一致可自动关联为重复；语义 `duplicate` 默认待人工确认。`new_progress` 需关联候选及新增事实证据，输出合法且相关性通过时可按自动入库开关新建并关联；低相关、不确定、日期未知/冲突、分析失败均保留待筛选，绝不自动删除原始内容。关闭分析时疑似更新同样待筛选。
- 默认 `analysis_apply_policy=suggest_only`。可显式选择 `fill_empty`，只补空摘要、未分类字段、无人工编辑记录的标签集合；已有分类只能引用有效分类 ID，新分类/标签候选须人工确认后创建。每字段记录人工维护来源和元数据版本；异步自动应用必须比较版本，不能覆盖分析期间的人工修改。人工采用建议也需提交基准元数据版本，冲突返回 409。
- 分析失败时不自动入库；有权限用户可明确“保留为待筛选素材”，填写原因，状态为 `pending_review`。此动作不伪造分析成功、不触发自动创作。已被忽略/归档/删除的对象不因分析重试而自动恢复或入库。
- 启用分析的产物只有当前正文分析成功、相关性通过/不适用、时间和去重决策可用且入库完成后才产生一次素材就绪事件；关闭分析时沿用基本入库就绪判断。人工待筛选资料需显式确认可用才可触发。阶段 5 消费事件并执行其原有六类条件检查；阶段 3 不依赖创作表或创建创作任务。

## 5. 状态、恢复与预算

- 运行记录配置快照、固定时间窗口、模型/搜索配置版本。候选持久化发现、抓取、解析、筛选和入库结果；分析具有独立 `pending/running/succeeded/failed/skipped` 状态，正文版本不匹配的历史结果在 API 标为 `stale`，不得当作当前结果应用。
- 每步记录尝试、错误、起止时间与计数；运行仍使用 `pending/running/succeeded/partial/failed`。搜索成功但零命中为成功空结果（原因 `no_results`）；已完成的相关性排除/待人工判断不是技术故障；有可保留结果且部分必要步骤失败或预算耗尽为 `partial`，没有可保留结果且发生技术失败或预算耗尽为 `failed`。分析未终结不能提前把整次运行标为成功。取消使用既有 async_job 的 cancelled 状态，运行结束原因标记 cancelled，已留存结果为 partial、无结果为 failed；前端优先显示“已取消”，不误报普通技术失败。
- `discovered/fetched/parsed/analyzed/materialized/filtered/review_required/failed` 分别计数；运行失败项按候选去重，阶段失败计数另列，避免一个候选多次失败被当成多篇文章。
- 默认单次搜索 30 秒、抓取 10 秒、模型调用 60 秒，每步最多 3 次尝试；每次运行最多 3 次搜索请求、40 次模型请求、600 秒执行时间，失败重试消耗同一预算。模型配置必须明确单次输入/输出 token 上限，预算在调用前检查并保存实际 usage；未知用量不显示为零或精确费用。限额停止保留部分成果和原因，不无限补搜。
- 网络瞬时失败可有限自动重试；鉴权/不支持能力/非法输出等保留明确错误，人工修正后重试。已完成搜索和抓取不因分析重试重复执行。提供方已计费而本地落库失败时，外部请求可能重复，不能承诺恰好一次调用或零重复计费；业务产物仍需幂等。
- 同一采集结果、正文 hash、分析配置版本、提示词版本、任务主题/关键词指纹、用途构成分析逻辑键；比较任务另含候选修订集合指纹。相同请求复用成功结果或重试原失败运行，attempt 追加留痕；改变输入/配置产生新分析记录。已入库素材的显式分析通过素材修订 ID 绑定，不复用其他主题的相关性判断。

## 6. 候选选型、迁移与验收

Tavily Search、feedparser、Trafilatura 分别作为搜索、RSS、正文提取的候选，尚未安装或确认。任务 3.13 使用固定中文样例比较至少 3 类目标来源（新闻、行业、官方公告），包含 RSS、多文章栏目、时间缺失和跨站转载；记录链接召回、正文完整性、日期准确性、延迟、配额和费用。每类至少 5 个已标注样例，列出逐条通过/失败及支持范围，不用演示结果宣称任意站点可用；正式选型与限制写入独立记录。不支持严格域名过滤的提供方必须由服务端补验，能力缺口不能伪造支持。

公共模型配置表与凭据/连接测试/调用 adapter 提前至 3.15–3.16，搜索配置同阶段接入，阶段 5 复用并增加文章生成校验。使用当前 Alembic head 之后的增量迁移，旧任务回填 `mode=source`、`analysis_enabled=false`、`web_page.page_kind=article`，不重放历史任务或改写正文/审核/引用；新增 nullable 列、回填、验证后再收紧约束，不修改已执行迁移。旧客户端省略字段走默认值，更新时省略新增字段保留原值；所有新字段和状态需前端兼容后启用。

3.28 完成增强独立验收；旧阶段 3 的 fixture 及被跳过的集成测试不算增强验证。扫描 PDF OCR、复杂动态网页、登录/验证码处理、自主反复搜索均不在本期交付；返回明确不可用原因。相关未验收证据见[缺口记录](../development/collection-enhancement-gaps.md)。
