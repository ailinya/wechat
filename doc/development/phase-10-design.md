# 阶段 10：增强功能设计与评估口径

## 范围和安全边界

阶段 10 只提供候选、关联建议、质量提示和事实报表；任何建议都不能创建已审核文章、修改审核记录或确认发布。复用既有八个一级模块、素材当前修订、文章固定修订及运营事实表。外部模型数据视为不可信输入；证据必须指向本次输入的素材/文章修订及原文片段。模型失败、超时或输出不合规时记录失败，保留原有编辑审核流程。真实公众号发布仍需单独授权。

## 输入、输出及接口

所有写请求须验证登录、相应权限和 CSRF；读取同时验证所有涉及领域的读取权限。数据库事务不得持有锁等待外部模型。持久化记录包含发起用户、输入修订、算法/提示词及模型配置版本、状态、结果、耗时及可得的 token 用量；不记录密钥。模型成本若供应商未提供价格或用量，显示未知而非零。

| 能力 | 输入与输出 | 权限与成本 |
| --- | --- | --- |
| 主题推荐 | 用户指定最多 20 个当前素材修订及可用分析模型；输出候选主题、采用素材及证据、现有文章重复提示。结果只供人工选择，不创建文章。 | `creation:write`、`material:read`、`article:read`；每次最多一次有预算的模型调用，记录模型版本与用量。 |
| 素材关联 | 用户指定一个当前素材；基于阶段 4 检索生成有限候选，记录两端修订、算法版本、分数及命中依据；用户可忽略建议。自动建议单独存储，绝不覆盖 `material_relations`。 | 生成及读取需 `material:read`、`material:search`，忽略另需 `material:write`；最多一次嵌入调用，降级明示。 |
| 历史检索增强 | 以现有检索为基线，保留范围、状态、修订及来源约束；关联建议仅在用户选择时用于扩展，并记录查询、算法、实际修订和降级状态。 | `material:read`、`material:search`；最多一次嵌入调用，记录延迟及可得用量。 |
| 质量建议 | 用户指定文章当前修订及分析模型；输出事实核验、来源及结构建议，每条展示证据/局限。无依据的模型断言不作为事实；输出不改变审核/发布状态。 | `article:read`、`material:read`；每次最多一次有预算模型调用；失败不阻塞业务。 |
| 复用和账号分析 | 素材按不同文章、不同文章修订分别去重；账号按发布单、发布尝试及人工登记分别计数。微信指标沿用既有最新快照及可用性语义，不将未知视为 0。 | `analytics:read` 与 `material:read`、`article:read`、`publish:read`、`account:read`；只读数据库，不调用外部服务。 |

接口统一使用 `/api/v1/assistance`：主题推荐 `POST /topics`、执行记录 `GET /runs/{id}`；素材关联生成 `POST /materials/{id}/relations`、查看 `GET /materials/{id}/relations`、忽略 `POST /relations/{id}/ignore`；增强检索 `POST /search`；质量评估 `POST /articles/{id}/quality`；复用和账号分析 `GET /analytics/reuse`。写操作使用现有 CSRF 和错误信封。模型参数、输入修订、建议与失败状态均可由执行记录追溯。

执行记录只允许发起人读取，并按类型重新检查对应业务权限。返回 `kind`、`status`、`algorithm_version`、`model_snapshot`、`input`、`result`、`usage`、`error_code`、`elapsed_ms` 和 `materials`（素材及修订 ID）；主题的 `result.candidates` 包含标题、理由、证据和重复文章，质量检查的 `result.suggestions` 包含类别、建议、局限与文章/素材证据。关联生成返回 `run_id`、检索模式、降级原因和 `items`；增强检索返回既有检索字段、`algorithm_version` 和 `run_id`。报表按页返回素材、文章和修订计数及账号明细。当前 OpenAPI 对上述动态结果使用宽泛对象，具体字段以本说明及前端类型为准。

检索向量预取后若配置 ID 或版本发生变化，则降级为关键词检索并记录原因，不将旧向量用于新配置。报表每页最多 100 个素材，按素材和账号读取多个聚合结果；大规模数据的报表延迟尚未实测。

## 固定验收样例

检索沿用 [阶段 4 的三素材四查询](material-search-evaluation.md)，增加历史素材、两条相关素材和无关素材的固定样例；相同查询分别执行首版和增强版，记录每题相关集合、Recall@k、误命中、服务端延迟和降级/模型用量。无改善或退化原样记录。阶段 4 基线包含真实 embedding 调用；离线 fixture 对比只能证明可重复的功能效果，不能与真实模型延迟混同。

主题样例至少包括重复标题、两个可关联素材和无关素材；检查候选所引用修订、可解释依据、同主题提示、重放一致性和不自动生成文章。质量样例至少包括有来源的陈述、无引用数字、缺少小标题的短文和完整结构文章；记录每条建议的证据、人工判断、误报、漏报及模型费用/未知值。运营样例包含一个素材在同一文章两个版本和另一篇文章被引用，同一文章的两个账号发布单、重试及不可获取的微信指标；预期分别为两篇文章、三个文章修订、两个发布单，并单独计算尝试。

评估记录须区分测试作者预设答案与有身份、时间和依据的人工标注；不得把模型生成或自动测试期望冒充人工标注。若缺少人工标注，仍可完成代码和离线测试，但 10.8/10.9 不能以自动测试冒充最终验收。
